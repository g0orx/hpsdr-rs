# RX-888 Mk2 (receive-only direct-sampling SDR)

> **Confirmed against real hardware.** Reception, tuning, gain, multiple
> simultaneous receivers, WSJT-X decoding via TCI, live local audio, and
> the spectrum/waterfall display have all been tested and confirmed
> working. If you hit something that doesn't match this chapter, reports
> are very welcome.

An RX-888 Mk2 is a receive-only, direct-sampling HF SDR (Cypress FX3 USB
controller + LTC2208-class ADC) that streams its *entire* captured
bandwidth as raw ADC samples over USB, with no on-board tuner or DDC of
its own -- hpsdr-rs does the digital down-conversion (an NCO mixer + CIC
decimator, one independent instance per receiver) itself in software.

![Screenshot needed: RX-888 connected, tuned to a signal, main window overview](images/20-rx888-main-window.png)

Because there's no on-board tuner, it isn't limited to the ham bands the
way a transmit-capable radio's front end usually is -- see
[**Gen**](02-main-window.md#bands-and-modes) on the main window for
jumping anywhere across its full captured range, and TX-safety concerns
don't apply at all (this hardware can't transmit).

## One-time setup

1. **Firmware** -- the Cypress FX3 RAM image (`SDDC_FX3.img`) is
   **bundled with hpsdr-rs** (MIT-licensed; its own real upstream is
   documented in `assets/rx888/PROVENANCE.md` in the source tree) -- no
   setup needed by default. Point the Discover window's **RX-888 USB
   setup** section at a different copy via **Choose...** only if you want
   to override it.
2. **Linux only**: install the udev rule for non-root USB access. Copy
   `assets/90-rx888.rules` (from the hpsdr-rs source, or
   `/usr/share/doc/hpsdr-rs/90-rx888.rules` if installed via the `.deb`)
   to `/etc/udev/rules.d/`, then either replug the device or run:
   ```sh
   sudo udevadm control --reload-rules && sudo udevadm trigger
   ```
3. **Windows only**: bind a WinUSB driver to both the unloaded
   (`04b4:00f3`) and loaded (`04b4:00f1`) PIDs using
   [Zadig](https://zadig.akeo.ie/), same reasoning as Ozy's `fffe:0007`.
4. **macOS**: no extra driver needed.

## Connecting

Plug in the RX-888 and click **Rediscover** -- it appears in the list as
board **Rx888**, with "USB" in place of an IP address.

The **Status** column shows a **possibly too slow** hint if the USB link
looks slower than this board's fixed data rate needs (e.g. a USB 2 cable
or hub) -- it's a best-effort warning, not a hard block, since it can't
always tell a genuinely slow link apart from a device that just hasn't
finished loading its firmware yet. If the link really is too slow,
connecting fails outright with a clear error instead of silently
streaming corrupted audio.

Select the row and click **Start**, same as any network radio.

![Screenshot needed: Discover window showing an Rx888 row, and the RX-888 USB setup section](images/20-rx888-discover.png)

## Sample rate

[Settings: RX](15-settings-rx.md#sample-rate)'s Sample Rate buttons offer
**96, 192, 384** kHz for this board, not the full range a real P1/P2
radio offers -- each has to land exactly on one of a small set of rates
WDSP's own internal resampler recognizes, and an RX-888's ADC clock has
to be reprogrammed to hit some of them exactly, which briefly interrupts
streaming (stop, reprogram, restart) rather than being a live change the
way it is on real hardware.

## Multiple receivers

Up to **8** simultaneous, independent receivers are supported -- see
[Extra Receivers](03-extra-receivers.md). Unlike a real P1/P2 radio,
there's no hardware wire-capacity limit behind this number: the RX-888
always streams its entire captured bandwidth regardless of how many
receivers are tuned into it, so each additional one is purely a software
cost. Each receiver's own down-conversion runs on its own CPU core in
parallel, so adding receivers spreads load across cores rather than
piling it onto one -- confirmed comfortable up to 8 on an 8-core/16-thread
machine with headroom to spare, but the practical ceiling depends on your
own CPU.

## Gain

The existing **RX Attenuation** slider ([Settings:
RX](15-settings-rx.md#rx-attenuation--rx-gain)) controls this board's own
step attenuator (0-31 dB). There's no separate RX-888-specific gain
control.

## Differences from network-connected boards

- **Receive-only.** No TX, no PA Calibration, no Diversity, no
  PureSignal -- this hardware has no transmitter and only one ADC.
- **No Open Collector / Antenna tabs.** No relay outputs or antenna-port
  switching hardware to control.
- See [Settings: About](04-about.md) for what the About tab shows for an
  RX-888 connection specifically ("USB" in place of network details).
